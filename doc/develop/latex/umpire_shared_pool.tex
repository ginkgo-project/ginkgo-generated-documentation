The Umpire shared pool example..

This example depends on simple-\/solver.

 \label{_umpire_shared_pool_Intro}%
 \label{_umpire_shared_pool_Introduction}%
\doxysection*{Introduction}

This example shows how an application that manages its own memory with \href{https://github.com/LLNL/Umpire}{\texttt{ Umpire}} can have Ginkgo allocate from the very same pool.

The application does the entire Umpire setup\+: it picks the memory resource, creates a {\ttfamily Quick\+Pool} over it, and registers that pool under a name of its own choosing. It then builds an executor with the matching Ginkgo allocator -- \mbox{\hyperlink{classgko_1_1UmpireCpuAllocator}{gko\+::\+Umpire\+Cpu\+Allocator}}, \mbox{\hyperlink{classgko_1_1UmpireCudaAllocator}{gko\+::\+Umpire\+Cuda\+Allocator}} or \mbox{\hyperlink{classgko_1_1UmpireHipAllocator}{gko\+::\+Umpire\+Hip\+Allocator}} -- which looks the pool up by that name in Umpire\textquotesingle{}s {\ttfamily Resource\+Manager}. From then on every Ginkgo allocation is served out of memory the application has already reserved, and the application sees Ginkgo\textquotesingle{}s usage in Umpire\textquotesingle{}s own statistics.

The reason to share a pool is that the alternative wastes device memory\+: an application pool sized to the device leaves Ginkgo nothing to allocate, and sizing both of them to half the device wastes whichever half is idle.

The example solves a 2D Poisson problem with CG and then checks what the pool saw\+: that it really served Ginkgo\textquotesingle{}s allocations, that they came out of memory the application had already reserved rather than growing the pool, and that nothing was left behind once the solve went out of scope.

\label{_umpire_shared_pool_Notes}%
\doxysubsubsection*{Notes }

Ginkgo must be configured with {\ttfamily -\/D\+G\+I\+N\+K\+G\+O\+\_\+\+B\+U\+I\+L\+D\+\_\+\+U\+M\+P\+I\+RE=ON} for this example to be built, and the application has to link Umpire itself\+: Ginkgo links it privately and does not re-\/export it.

Umpire\textquotesingle{}s pools are not stream-\/ordered, so sharing a device pool across streams needs an {\ttfamily Executor\+::synchronize()} before freed memory is handed out again. \label{_umpire_shared_pool_CommProg}%

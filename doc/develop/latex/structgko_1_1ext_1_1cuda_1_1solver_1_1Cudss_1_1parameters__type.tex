cu\+D\+SS matrix type, mapping to {\ttfamily cudss\+Matrix\+Type\+\_\+t}\+: 


\begin{DoxyItemize}
\item 0 = G\+E\+N\+E\+R\+AL (unsymmetric)
\item 1 = S\+Y\+M\+M\+E\+T\+R\+IC (real symmetric)
\item 2 = H\+E\+R\+M\+I\+T\+I\+AN (complex Hermitian)
\item 3 = S\+PD (symmetric positive definite)
\item 4 = H\+PD (Hermitian positive definite)
\end{DoxyItemize}

\begin{DoxyWarning}{Warning}
Ginkgo\textquotesingle{}s \mbox{\hyperlink{classgko_1_1matrix_1_1Csr}{gko\+::matrix\+::\+Csr}} stores the full matrix. cu\+D\+SS expects that when {\ttfamily matrix\+\_\+type} is S\+Y\+M\+M\+E\+T\+R\+IC / H\+E\+R\+M\+I\+T\+I\+AN / S\+PD / H\+PD, the supplied C\+SR contains {\bfseries{only}} the triangle indicated by {\ttfamily matrix\+\_\+view} (plus the diagonal). Passing a fully-\/stored symmetric matrix with one of these types is not the documented input contract and can produce incorrect results. To use the symmetric factorizations, extract the upper or lower triangle into a new C\+SR before constructing the solver. For a fully-\/stored matrix, use G\+E\+N\+E\+R\+AL (0) together with {\ttfamily matrix\+\_\+view = F\+U\+LL} (0). 
\end{DoxyWarning}

cu\+D\+SS matrix view, mapping to {\ttfamily cudss\+Matrix\+View\+Type\+\_\+t}\+: 


\begin{DoxyItemize}
\item 0 = F\+U\+LL (entire matrix stored in C\+SR)
\item 1 = L\+O\+W\+ER (only strictly-\/lower + diagonal stored in C\+SR)
\item 2 = U\+P\+P\+ER (only strictly-\/upper + diagonal stored in C\+SR)

This tells cu\+D\+SS what the C\+SR data actually contains; it is not a filter applied to a fully-\/stored matrix. Use F\+U\+LL (0) for unsymmetric matrices and when passing a fully-\/stored symmetric matrix with {\ttfamily matrix\+\_\+type = G\+E\+N\+E\+R\+AL}. Use L\+O\+W\+ER / U\+P\+P\+ER only when the C\+SR itself stores just that triangle (in combination with {\ttfamily matrix\+\_\+type} S\+Y\+M\+M\+E\+T\+R\+IC / H\+E\+R\+M\+I\+T\+I\+AN / S\+PD / H\+PD).
